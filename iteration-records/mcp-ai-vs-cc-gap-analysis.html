一、结论

ai 与 Studio/CC 现在都能作为独立 MCP client 完成配置、传输、认证、发现、调用和会话清理。两者不会源码级完全相同：Studio/CC 还有自己的 IDE、企业和插件宿主能力；这些不是 MCP 公共协议的必要组成。

本轮纠正：早期报告把 OAuth、Prompts、WebSocket、动态通知和大结果落盘列成 ai 不支持，这是过时结论；相关能力现已实现并加入测试。

四、仍由 Studio/CC 提供的产品层能力

下面保留“是什么、例子和影响”，但不再把已经完成的标准 MCP 能力误列为缺失。

逐 Server / 逐工具权限审批

安全

是什么：首次启用项目 server 时确认信任；每个工具配置 allow、deny 或 ask。

CC：项目审批和工具权限接入统一安全系统。ai 当前把用户已配置或项目声明的 server 视为可信。

例子：仓库声明未知 npm server，或数据库 MCP 暴露 drop_database；CC 可在启动和调用两层拦截。

影响：共享仓库和生产写操作仍需人工审查。

完整 Elicitation UI

交互

是什么：server 在执行中要求用户填表、确认或访问 URL，再继续调用。

CC：表单、URL、hooks 和对话框完整串联。ai 已注册 handler，但当前安全返回 cancel。

例子：部署工具询问目标环境和生产确认；CC 展示表单，ai 当前取消该 elicitation。

影响：需要人在环补充信息的 server 无法完成整条流程。

Managed / Enterprise / Plugin 策略

企业

是什么：组织下发/锁定 MCP，插件声明 server，并按来源和签名去重。

CC：具有 managed、enterprise、plugin、claude.ai 等来源；ai 当前只有 local、user、project。

例子：组织和插件同时下发 Slack MCP，CC 自动保留优先级更高的一份。

影响：个人使用不受阻，企业规模治理仍有差距。

私有 In-process / IDE Transport

宿主

是什么：把 IDE、浏览器或 Computer Use server 作为宿主内部对象挂载，而非走公开 transport。

CC：这些 transport 与自身应用生命周期绑定，不是可复制的通用 endpoint。

例子：CC 把编辑器选区以内存对象方式暴露给内置 server；ai 可连 WS，但不能加载 CC 私有对象。

影响：只影响 Studio/CC 内建集成，不影响第三方标准 MCP。

完整管理面板与 OS Keychain

体验

是什么：TUI 内展示状态、认证、工具和开关，并把 token 放进系统凭据库。

CC：有完整面板与 OS 凭据集成。ai 提供 CLI，凭据以独立 0600 JSON 保存。

例子：CC 可点击重连；ai 使用 test、auth、logout。

影响：主要是可发现性和本机凭据防护层级。
